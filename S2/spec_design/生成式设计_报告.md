# 一阶临界转速规格驱动的生成式设计：技术报告

日期 2026-09-25。代码 `S2/spec_design/`，数据 v4.7（`S1/04_versions/v4.7/dataset_v4.7/dataset_v4.7_all.csv`，success 199811 台）。
本文件是把此前逐轮产生的六份报告合并成的单一技术报告，按「表示、生成、选择、家族、基线、复验」分层组织；怎么运行见 `README_初版生成式设计_v1.md`。

## 0. 摘要

用户给「材料 + 目标一阶临界转速 + 容差」，可选给盘数与轴承数的约束；系统返回一批互不相同、几何合法、经 ROSS 真值复验的设计。

一条查询经过五层：约束内隐空间表示（34 维，硬约束按构造满足）、条件 DDPM（13 维条件，v 预测，25 步采样）、代理排序（5 seed 多输出 MLP，取前 200）、家族策略（自由 / 范围 / 钉死）、ROSS 复验（18 进程，含硬件校准）。

关键结果：

| 项目 | 结果 |
|---|---|
| 直接生成 33 维原始设计的合法率 | 6.9%（因此必须换坐标） |
| 隐空间解码后的合法率 | 1.0000（7200 个随机隐向量，0 违反） |
| 代理精度（一阶） | R2 0.9935，MAPE 2.79%，中位 APE 1.50% |
| 生成配置（模型 armV_ema，25 步，当前 out-tag `v1`）真值在带率 | 0.963（rand-40 抽查，六规格平均）；本次复核 rand-20 为 0.933 |
| 优化类基线真值在带率 | DE 0.348、Adam 0.575、GA 0.750、BO 0.125 |
| 检索基线 | 真值在带 1.000，但新颖度 0（复制已有设计） |
| 代理乐观偏置（自称在带 − 真实在带） | DE +0.652、Adam +0.425、GA +0.250、本版 +0.058 |

用户还能给三种形式的目标，并且有一条单入口命令直接出结果（`design_by_target.py`，同时给 CSV 与人可读的设计清单 `*_sheet.md`）：双侧带、单侧要求（一阶不低于某值）、任意材料与任意转速，并可限定盘数与轴承数的区间（`--fam-allowed 3-3/2-4`）。

本轮把三条边界重新量过（n=150 真值，此前的 20 台抽样不够）：

| 问题 | 结论 |
|---|---|
| 限定家族是否提高在带率 | 不提高。同一目标 ±5% 下：18 家族 0.960、盘 3 轴承 2 到 4 为 0.953、钉死 3x2 为 0.987；两两 Fisher 检验 p = 0.17 到 1.00，差别在噪声内。家族是用户约束，不是性能杠杆 |
| 事后校准能否救紧带 | 不能。单参数目标偏移在 4 条臂上 0 条受益（top-20 平均 −0.013），十特征偏置层的 r² 也只有 0.13 |
| 容差能收到多紧 | 容差是主旋钮：±5% 时真值在带 0.95 到 0.99，±1% 时 0.52，±0.5% 时 0.22。数据侧中位档能支撑 ±0.5%，但代理自己的中位 APE 是 1.04% 到 1.14%，所以中位档是代理在限制，上尾档才是数据先到极限 |

未解决：整批（5000）的代理在带率约 0.18，与交付清单不是同一口径；紧带交付要靠加宽容差或把 ROSS 放回循环；代理排序在 ±1% 以下不可救。

## 1. 任务定义

旧思路要求用户给出六阶临界转速的精确目标，并固定切片 `nd=3, nb=2`。工程实际不是这样：用户手上只有一个工况，再由工程惯例换算成对一阶临界转速的要求，形式是「目标值 + 容差」。因此本阶段把任务改成点目标反解。

- 输入：材料、一阶临界转速目标值、容差（可选：盘数与轴承数的取值或范围）
- 设计变量：全部几何尺寸，以及默认情况下的盘数与轴承数
- 输出：一批互不相同、可制造、真值落进容差的设计

六个规格（`outputs/specs.json`）：

| 规格 | 材料 | 档位 | 目标 cs1 | 容差 | 家族自由的真实解数 | 固定 nd=3,nb=2 的解数 |
|---|---|---|---|---|---|---|
| Steel_mid | Steel | 中位 | 3600 | ±5% | 2656 | 166 |
| Steel_high | Steel | 上尾 | 16000 | ±5% | 970 | 23 |
| Aluminum_mid | Aluminum | 中位 | 5100 | ±5% | 2709 | 163 |
| Aluminum_high | Aluminum | 上尾 | 23000 | ±5% | 874 | 24 |
| Titanium_mid | Titanium | 中位 | 4300 | ±5% | 2720 | 180 |
| Titanium_high | Titanium | 上尾 | 19000 | ±5% | 912 | 23 |

最后两列的差距就是「放开家族」这一决定的量化依据：同一个容差，家族自由时可行设计有十倍以上的量。

## 2. 评估协议（冻结）

- 判据：一阶临界转速落在目标 ±5% 内。上尾规格另记 ±2% 可达精度（该带位真实解更少）。
- 指标：代理在带率、**真值在带率**、MAPE、中位 APE、新颖度（到池子最近设计的距离，以池子自身尺度为单位）、ROSS 求解失败率与超时数。
- 两种抽查口径，不能混说：
  - `rand-40`：在提交的 200 台里随机抽 40 台，检验「这批设计本身对不对」，不经过代理排序；
  - `top-40`：抽代理排序最靠前的 40 台，检验「交付清单对不对」。
- 每次复验都带 12 台数据集里已标注的设计做硬件校准，当前中位偏差 0.03%，最大 0.005%。

### 2.1 用户能给出的目标形式

| 形式 | 命令 | 判据 |
|---|---|---|
| 双侧带 | `--target 5000 --material Steel --tol 0.05` | cs1 落在 4750 到 5250 rpm |
| 单侧要求 | `--target 5000 --material Steel --spec-mode lower --tol 0.02` | cs1 不低于 5000 rpm，瞄准 5100 |
| 家族区间 | 追加 `--fam-allowed 3-3/2-4` | 盘 3、轴承 2 到 4，三个家族 |
| 单入口 | `design_by_target.py --target 5000 --material Steel --disks 3-3 --bearings 2-4` | 采样 + 清单一步到位 |

单侧模式下 `--tol` 的含义从「带半宽」变成「瞄准余量」：排序目标放在要求线之上 2%，而不是压在要求线上。为什么必须这样，见第 8 节的 `lb5000` 与 `lb5000_m2` 两行（真值在带 0.733 到 0.960）。

目标值不受限，只要落在该材料有数据支撑的区间里。材料自身的量程（池子，rpm）：Steel 中位 3642、p99 25544、最大 73143；Aluminum 5137 / 38398 / 129822；Titanium 4342 / 31769 / 112347。

### 2.2 目标可达性：数据与代理谁先到极限

`02d_tol_support.py` 把两件事放在一起算（`outputs/tol_support.json`）：池子里落在目标 ± 容差内的真实设计数，和代理自己的误差。交付清单长 200 台，所以「可行容差」定义为该容差下仍有 200 台以上真实解。下表每格是「最紧可行容差（该容差下的真实解数）」。

| 材料 | p10 | p25 | p50 | p75 | p90 | p95 | p99 |
|---|---|---|---|---|---|---|---|
| Steel | ±0.75% (264) | ±0.50% (253) | ±0.50% (275) | ±0.75% (309) | ±1.00% (273) | ±1.00% (213) | ±5.00% (245) |
| Aluminum | ±0.75% (241) | ±0.50% (254) | ±0.50% (275) | ±0.50% (217) | ±0.75% (208) | ±2.00% (370) | ±5.00% (266) |
| Titanium | ±0.75% (259) | ±0.50% (243) | ±0.50% (288) | ±0.50% (224) | ±0.75% (227) | ±2.00% (373) | ±5.00% (245) |

代理在 cs1 上的中位 APE（整个池子）：Steel 1.04%、Aluminum 1.14%、Titanium 1.10%。

两句话读法：中位与下尾的可行容差（±0.5%）比代理的误差（约 1.1%）还紧，所以那里**瓶颈是代理，不是数据**；到 p95 只有 ±1% 到 ±2%、p99 只剩 ±5%，那里**瓶颈换成了数据**。给用户报可达性时要同时看这两条线。

## 3. 表示层：约束内隐空间（34 维）

代码 `latent_design.py`。

原始 33 维设计受六条耦合硬约束支配（盘外径对轴外径、盘间隙、轴向边距、轴承与盘的间距、长径比、轴承刚度比）。直接生成它实测只有 6.9% 合法，裁剪救不了：约束互相耦合，而且单位立方体条件数很差，轴承刚度跨 2.7 个数量级，±30% 的刚度比只占这个立方体 0.6% 宽的薄片。

做法是把设计改成 34 维隐向量 u，每一维都在 [0,1] 内独立自由，六条约束由解码器按构造满足：

| 约束 | 在隐空间里怎么表达 |
|---|---|
| H1 盘外径 > 1.05 倍轴外径 | `expm1` 盒子，增量恒为正 |
| H2 盘间隙 >= 半宽和 + 3 mm | 坐标给的是**累计间隙的切点**，切点天然单调 |
| H3 位置在 [0.1L, 0.9L] | 边距由 L 算出，位置只在边距内铺开 |
| H4 轴承避开盘（±10 mm） | 轴承位置是「自由区间上的累计比例 u」，自由区间按 L 与盘位置动态算 |
| H5 长径比范围 | 解码时把 OD 裁进 (L/50, L/2) |
| H6 刚度极差 <= 1.857 倍 | 刚度写成「最小刚度对数 + [0, ln(1.3/0.7)] 的偏移」 |

验证（`基线重写_隐空间对照_报告.md` 的第一节）：

| 检查 | 结果 |
|---|---|
| 7200 个随机隐向量解码后的合法性 | 1.0000，0 个违反 |
| torch 版与 numpy 版解码器的逐元素最大相对差 | 1.0e-15 |
| Adam 的梯度 | 有限，且只落在该家族启用的坐标上 |

附带好处是归一化问题自动消失：34 维全部是 [0,1]，量纲统一，训练不需要再做 z-score。

## 4. 生成层：条件 DDPM

代码 `05_latent_ddpm.py`，噪声表复用冻结的 `S2/DDPM_v47/02_ddpm.py`。

- 条件 13 维：材料 one-hot(3) + 家族 one-hot(9) + z(log 目标转速)。训练时目标填该样本真实的 cs1，采样时填用户给的目标，于是同一个网络既是前向的代理又是反解器。
- 家族两处同时作用：条件里告诉网络是哪个家族，隐向量里用掩码把该家族不用的槽位钉 0 并从损失排除。
- 网络：时间正弦编码过两层 MLP 得时间嵌入，与 [隐向量, 条件] 拼接后过 hidden 层输出同维预测。`time_dim=64` 时逐字节复用冻结的 `Denoiser`。
- 训练：cosine 噪声表 T=1000，v 预测（`v = sqrt(abar)·eps − sqrt(1−abar)·x0`），masked MSE，EMA 权重，条件 dropout 0.10 以支持 classifier-free guidance。
- 采样：默认 25 步跨步跳采样，步长用 `abar[t]/abar[t_prev]` 的精确比值；每步结束乘一次家族掩码。

开关逐个做过 A/B（rand-40 口径，真值在带 / MAPE / 中位 APE）：

| 配置 | rand-40 结果 |
|---|---|
| eps，1000 步，g1.0（原版基线） | 0.799 / 3.39% / 1.84% |
| v，1000 步，无 EMA | 0.887 / 2.42% / 1.56% |
| v，1000 步，EMA | 0.871 / 2.50% / 1.73% |
| v，250 步，EMA | 0.875 / 2.56% / 1.32% |
| v，100 步，EMA | 0.900 / 2.01% / 1.36% |
| v，50 步，EMA | 0.916 / 2.22% / 1.42% |
| **v，25 步，EMA（推荐，即 v1）** | **0.963 / 1.58% / 1.02%** |
| v，25 步，EMA，换种子 | 0.925 / 1.86% / 1.22% |
| v，10 步，EMA | 0.958 / 1.44% / 1.07% |
| v，5 步，EMA | 0.896 / 1.12% / 0.82% |
| v，1000 步，EMA，g1.5 | 0.862 / 2.27% / 1.46% |
| 384×6 窄而深（1.09M），v，EMA，25 步 | 0.954 / 1.69% / 1.28% |
| 256×6（0.50M），v，EMA | 0.854 / 2.80% / 1.73% |
| min-SNR 5，v，1000 步，g1.5 | 0.787 / 3.52% / 1.78% |

逐条结论：

- **有效**：训练目标换成 v（0.799 到 0.887）；采样步数从 1000 降到 10 到 25（0.871 到 0.963，25 步是甜点，5 步开始掉）；等参数量下窄而深（384×6 对 512×3，精度更好）。
- **只体现在精度**：窄而深结构把 MAPE 从 2.32% 压到 2.18%、中位 APE 从 1.61% 压到 1.32%，命中率基本不动。
- **无增益**：EMA（命中 0.871 对 0.887，在噪声内，但精度稳定，故保留）。
- **有害**：min-SNR 损失加权（0.787）、容量减半（0.854）。
- **与命中无关**：guidance（0.75 到 2.5 全在 0.854 到 0.871 之间）。

## 5. 选择层：代理与它的乐观偏置

代理是 5 seed 多输出 MLP（1024-512-256，L1 损失，log 目标，log 空间几何平均集成），权重在 `S2/surrogate_v47/outputs/mlp_v47_best/`。

| 目标 | R2 | R2(log) | MAPE | 中位 APE |
|---|---|---|---|---|
| 一阶 cs1 | 0.9935 | 0.9964 | 2.79% | 1.50% |
| 六阶平均 | 0.989 | 0.992 | 4.44% | 2.43% |

特征必须走与训练完全同源的路径（`spec_common.canonical_to_model_rows` 到 S1 约束模块到 MLP 特征工程，47 维），其中 5 列要先取 log 再标准化，列索引只存在 `summary_mlp.json` 里。

**问题**：代理在分布外偏乐观。选择层在生成器外面还有一个前提没被检验，就是「代理说在带内」是否等于「真值在带内」。

三个免费信号（`uncertainty_signals.py`）：5 个 seed 的 `spread`、特征空间 `dF`、几何空间 `dD`、箱体越界 `box`。

| 信号 | spearman(log 误差) | 单独 R2 |
|---|---|---|
| spread | 0.414 | 0.161 |
| dF | 0.245 | 0.052 |
| dD | 0.225 | 0.043 |
| box | −0.044 | 0.000 |
| 四者合计 | | 0.168 |

**Stage A（留出测试集，分布内）**：代理本来是诚实的。

| 指标 | 值 |
|---|---|
| 中位 log 误差 | 1.51% |
| 代理自称 cs1 >= 14400 | 10.25% |
| 真实 cs1 >= 14400 | 10.33% |
| 误报率 | 0.32% |

按 spread 分五档看，误差随 spread 单调上升：Q1 中位 APE 0.93%、Q5 4.02%，误差超 5% 的比例从 2.3% 涨到 42.5%。所以 spread 可以当误差棒的长度。

**Stage B（36 个真实提交批次，1426 台 ROSS 真值）**：乐观偏置出现在提交上。

| 方法 | 代理自称在带 | 真实在带 | 乐观偏置 | 自称可信度 |
|---|---|---|---|---|
| de | 1.000 | 0.399 | +0.601 | 0.399 |
| adam | 1.000 | 0.603 | +0.397 | 0.603 |
| ga | 1.000 | 0.796 | +0.204 | 0.796 |
| v1（armV_ema + 25 步） | 1.000 | 0.942 | +0.058 | 0.942 |
| retrieval | 0.796 | 1.000 | −0.204 | 1.000 |
| bo | 0.118 | 0.109 | +0.008 | 0.299 |

**解决一：诚实误差棒。** 用平滑的、含新颖度信息的 0.9 分位数替掉分档常量：

    q90(|log 误差|) = exp(−0.965 + 0.754·log(spread) + 0.639·log(dF))

| 规则 | 覆盖率 | 保留比例 | 自称可信度 | 召回 |
|---|---|---|---|---|
| 常量 2.04（测试集拟合） | 0.840 | 0.246 | 0.962 | 0.359 |
| 常量 3.13（分布外重标） | 0.926 | 0.092 | 0.980 | 0.136 |
| **平滑棒（只用测试集）** | **0.853** | **0.225** | **0.979** | **0.334** |

结论：不需要分布外重标定，同等精度下保留的候选是原来的 2.4 倍。保守程度由 tau 旋钮控制，推荐工作点 0.80（保留 0.293、自称可信度 0.958、召回 0.426）。

筛选前后自称可信度的变化：de 0.399 到 0.900，adam 0.603 到 1.000，ga 0.796 到 0.977，本版 0.942 到 0.976。

**解决二：预算收益。** 给定每批次只能送 k 台进 ROSS 的预算：

| k | 协议挑法 | 诚实区间挑法 | 随机 |
|---|---|---|---|
| 5 | 0.667 | 0.828 | 0.642 |
| 10 | 0.658 | 0.800 | 0.642 |
| 20 | 0.661 | 0.743 | 0.642 |

配对检验：区间挑法减协议挑法 = +0.161（t=3.48）、+0.142（t=5.01）、+0.082（t=4.33）；协议挑法减随机只有 +0.025（t=0.97），即**协议自身的排序并不比随机好，收益全部来自诚实区间**。

**解决三：批内排序与退化标签。** 学一个岭回归偏置层，留一批法验证，并加门控（`平均 dF > 4.14` 或 `平均 spread > 0.0613`，圈出 adam / bo / de 共 18 批）。批内 spearman：de 从 −0.121 到 +0.255，ga 从 0.048 到 0.218，总体 0.310 到 0.360。加不确定度惩罚后预算曲线进一步升到 0.844 / 0.833 / 0.794。

退化标签用 `ross_guard.py` 的复现性判据（同一台用 num_modes 15 与 30 各解一次，20% 内一致才算真模态）。数据集自身 172 行低 cs1 全是真标签；本轮 3 台全是伪模态，修正后整体 MAPE 从 14044% 回到 8.07%。真值噪声用 12 批各补 60 条（719 次求解）量化：保留比例位移均值 +0.002、均方根 0.026，而 40 条样本的二项标准误是 0.056，所以逐批次数字要带 ±0.05 读。

**解决四：目标偏移（失败）。** 偏置层的符号是确定的（代理偏乐观），所以试过更省参数的版本：用 ROSS 样本拟合一个批量的中位对数偏移，把预测挪一下再重新排序（`proxy_calibration.shift_cross_fit`，五折交叉，同一批设计同一批真值，只有排序变；脚本 `tools/proxy_target_shift.py`）。

| 臂 | 目标形式 | 代理自称（抽中批） | 抽查真值 | 原排序 top-20 | 偏移后 top-20 | 拟合偏移 |
|---|---|---|---|---|---|---|
| t5000_t1 | 5000 ±1%（150 台） | 0.813 | 0.520 | 0.650 | 0.600 | +0.09% |
| t5000_t05 | 5000 ±0.5%（150 台） | 0.300 | 0.220 | 0.150 | 0.150 | −0.17% |
| lb5000 | cs1 ≥ 5000（150 台） | 0.920 | 0.733 | 0.650 | 0.650 | −0.17% |
| lb5000_m2 | cs1 ≥ 5000，瞄准 5100（150 台） | 1.000 | 0.960 | 0.950 | 0.950 | +0.12% |

4 条臂 0 条受益，top-20 平均增益 −0.013。这与十特征偏置层（r² 0.13、纠正后 MAPE 从 8.07% 升到 9.56%）的失败是一致的，所以**结论是事后校准这条路封掉了**：代理误差里可学的部分不足以支撑重新排序。

这里还量到一件对流程有用的事：**紧带下代理自称与真值的差距本身就是警报**。±5% 时差 0.058，±1% 时差 0.293（自称 0.813、真值 0.520），±0.5% 时差 0.080 但绝对值已经没用（0.220）。自称与真值的差在 ±1% 附近最大，因为那正是代理误差与被测带宽同量级的地方。

**解决五：把排序问题换成筛选问题（闸门）。** 解决四封掉了事后校准，所以先做一个更直接的排除实验：候选池从 5000 台拉到 25000 台，看紧带是不是「没挑够」。同规格（Steel 5000 rpm ±1%）、同 seed、同参数：

| 臂 | 生成量 | 代理自称（交付批） | 代理中位相对误差 | 真值在带 | MAPE | 中位 APE |
|---|---|---|---|---|---|---|
| t5000_t1 | 5000 | 0.830 | 0.61% | 0.520 | 1.54% | 0.80% |
| t5000_t1_g25k | 25000 | 1.000 | 0.10% | 0.525 | 1.38% | 0.94% |

候选多 5 倍，代理自称从 0.830 升到满分 1.000、自称误差降了 6 倍，**真值在带纹丝不动（0.520 到 0.525）**。这条证据同时排除「排序没挑好」与「候选不够多」，剩下的解释只有一个：代理误差本身不可约。紧带下代理能给的最好东西，就是一堆它自己分不出优劣的候选。

于是换掉问题：不要求代理会排序，只要求它值得被送检。`05_ross_verify.py --gate`（单入口里是 `design_by_target.py --verify`）把短名单逐台解 ROSS，只交付实测在带的那部分，代价可以按「交付一台要付几次求解」直接量出来：

| 容差 | 代理自称在带（200 台） | 真值在带＝闸门交付 | 每交付一台 |
|---|---|---|---|
| ±0.5% | 200 / 79 | 66 / 63 | 1.95 s / 2.08 s |
| ±1% | 200 / 166 | 105 / 103 | 1.22 s / 1.27 s |
| ±2% | 200 / 200 | 164 / 154 | 0.78 s / 0.85 s |
| ±3% | 200 / 200 | 182 / 172 | 0.71 s / 0.76 s |
| ±5% | 200 / 200 | 192 / 188 | 0.67 s / 0.70 s |
| ±10% | 200 / 200 | 199 / 198 | 0.65 s / 0.66 s |

口径：每格是「25000 台臂 / 5000 台臂」；短名单选取只与代理预测和目标有关，与容差无关，所以同一批 200 台真值可以免费读出整条曲线。每条都是一次 200 台求解（18 进程，墙钟约 128 秒），「每交付一台」＝该次墙钟时间除以实测在带台数。容差因此成了一个明码标价的旋钮：**±5% 及以上靠代理就够，±1% 必须付仿真钱，±0.5% 每台两秒**。同一张表也给出乐观偏置的交付版本：±5% 时代理自称 200 台全在带、实测 188 台，直接交付会夹带 12 台不合格品，过闸门后这 12 台被拦下，代价 0.70 秒一台。

一个必须写明的限度：±1% 的 0.525 是「**代理排前 200 台里有一半是真的**」，不是「生成的 25000 台里有一半是真的」。后者要单独量，见下。加大 `n-generate` 对闸门也没有意义：25000 台臂比 5000 台臂只多交付 2 台，采样时间却从 12 秒涨到 22 秒。

**排序值多少：把整条链路量出来。** 用 `05_latent_ddpm.py --dump-batch 300` 把整批的 300 台无偏样本落盘，再走同一套 ROSS（299 台解出、1 台超时），就得到每一级的在带率（全部 ±1%，Steel 5000 rpm）：

| 环节 | 在带率 | 相对上一级 |
|---|---|---|
| 池子：66377 台真实 Steel 设计，不筛选 | 0.0077 | |
| 条件 DDPM 生成 25000 台（300 台无偏抽样） | 0.0334 | 4.3x |
| 代理排序后取前 200 台 | 0.525 | 15.7x |
| 过闸门交付 | 1.000 | 1.22 秒/台 |

所以排序不是「没挑好」的环节，它值 15.7 倍；池子到批次的 4.3 倍是条件本身的功劳。三级的绝对值都低，是因为紧带本来就稀有：批样本的中位目标距离是 15.5%，即生成器把质量大致推向目标（±10% 内占 32.4%，池子只有 7.7%），但推得很散。散度对哪些旋钮敏感已经逐条量过：排序、候选数、容量、目标编码、条件强度、预测参数化（解决六到解决八）都不决定它；真正改得动它的是把可微代理接进反向链（解决九）。

**解决六：按代理自称预筛（不值得）。** 闸门表里 ±0.5% 那格看起来有省法：代理自称在带的只有 79 台，何必把 200 台都送验。用已存的真值就能算这条，不需要新求解：

| 容差 | 全送验：求解/交付 | 每交付一台 | 只送代理自称在带：求解/交付 | 每交付一台 | 省 |
|---|---|---|---|---|---|
| ±0.5% | 200/63 | 2.08 s | 79/27 | 1.92 s | 8% |
| ±1% | 200/103 | 1.27 s | 166/89 | 1.22 s | 4% |
| ±2% 及以上 | 200/154 起 | 0.85 s | 200 起 | 同左 | 0% |

省得很少，因为代理对自己「在带」的判断在紧带上几乎不含信息：±0.5% 时它自称在带的 79 台里只有 27 台是真的（精确率 0.342），±1% 时 166 台里 89 台（0.536）。要交付同样多的设计，预筛需 196 次求解、全送需 200 次，基本打平。所以没有加这个开关，闸门成本一律按「全送」口径写。

**解决七：去噪器容量（弱杠杆）。** 比较两个同训练配置、同 seed、200 epoch 的去噪器：`512x512x512`（0.90M 参数，现用）对 `256x256x256x256x256`（0.43M，即「窄而深」方向）。

| 模型 | 参数 | best val | 批样本中位目标距离 | ±1% | ±5% | ±10% |
|---|---|---|---|---|---|---|
| 512x512x512 | 0.90M | 0.17682 | 15.5% | 0.0334 | 0.151 | 0.324 |
| 256x256x256x256x256 | 0.43M | 0.18103 | 20.9% | 0.023 | 0.140 | 0.247 |

容量减半只让验证损失差 2.4%，却让批样本的 ±10% 份额掉 7.7 个百分点（约 2.8 个标准误）、中位距离涨 35%。两点结论：一是**用验证损失判断容量不够用**，它会低报影响；二是「窄而深」不是免费方向，缩宽度确实伤生成质量。反过来，±1% 那列 0.033 对 0.023 只差 1.0 个标准误，分辨不了，所以容量不足也不是紧带交付的拦路虎。决定：保留 `512x512x512`，不往容量继续投。

**解决八：目标编码、条件强度、预测参数化（都否）。** 第 9 节把整批散度记在「条件编码」账上：条件只给一个 z 化的对数目标标量，而 ±1% 是这个标量尺度上极窄的一段，ReLU MLP 只能用分段常斜率去分辨。顺着这条线各训一版，都与 `armV_ema` 同 seed、同 200 epoch、同 `--predict v --ema`，只动一个变量：

| 模型 | 改了什么 | 条件维度 | 参数 | best val |
|---|---|---|---|---|
| `armV_ema` | 基准 | 13 | 0.90M | 0.17682 |
| `armF` | 目标从 1 维标量扩成 9 维多尺度基（z 加 sin/cos 四组频率 `0.5 / 1 / 2 / 4`） | 21 | 1.13M | 0.17650 |
| `armD0` | `--condition-dropout` 0.1 到 0 | 13 | 0.90M | 0.17814 |
| `armX0` | 去噪器目标从 v 换成 x0（直接输出干净隐向量） | 13 | 0.90M | 0.03550（量纲不同，不可与上面比） |

验证损失三次都挤在 0.2% 到 1.5% 内，按解决七的教训这分辨不了什么，所以判据放生成侧：六个目标、每格 3000 台、`--sample-steps 25`、同 seed、代理口径（全表 `outputs/latent_ddpm/ab_25steps.csv`，每格是 ±1% / ±5% / 中位 \|rel\|）。

| 材料 | 目标 | z | fourier | dropout 0 | x0 |
|---|---|---|---|---|---|
| Steel | 3600 | 0.027/0.146/0.174 | 0.035/0.170/0.160 | 0.029/0.154/0.186 | 0.034/0.138/0.195 |
| Steel | 5000 | 0.029/0.175/0.160 | 0.037/0.172/0.160 | 0.033/0.167/0.171 | 0.028/0.141/0.192 |
| Steel | 8000 | 0.035/0.194/0.139 | 0.042/0.193/0.149 | 0.041/0.176/0.149 | 0.036/0.169/0.162 |

配对读法（同目标逐格相减，n=6）：多尺度编码的 ±1% 份额 +0.13 个百分点（se 0.28）、±5% −0.15（se 0.58）；`dropout 0` 的 ±1% −0.03（se 0.18）、±5% −0.91（se 0.51，t = −1.8）、中位距离 +1.1 个百分点；`x0` 的 ±1% +0.03、±5% −1.61（se 0.65，t = −2.5）、中位距离 +2.1 个百分点。**三条路都没有收窄条件分布，`x0` 还稳定略差。**

散度不是条件的分辨率、也不是条件的强度，三条证据：

- **家族内还是散**：25 步批次里，Steel 5000 rpm 下 18 个家族各自的中位 \|rel\| 落在 0.133（5 盘 2 轴承）到 0.220（1 盘 2 轴承），中位数 0.158，没有一个进 10% 以内（表在 `outputs/latent_ddpm/cond_encoding_by_family.csv`）。所以散度不是 18 个家族混在一起造成的。
- **宽的是核不是尾**：同一批的四分位是 −0.044 与 +0.261，四分位距 0.305，±1% 只占 2.9%。条件分布若近似正态、σ 取这个四分位距对应的 0.23，±1% 天然就只占约 3.5%，与实测相符。要让整批过半落进 ±1%，σ 得压到 0.02 量级。
- **瞄准偏置也不听条件的**：无引导批次在 Steel 5000 rpm 上的中位偏差是 +9.8%（代理）、+9.5%（真值），而它最后是被解决九的引导消掉的，不是被条件侧的任何改动。

结论：散度是去噪器学到的**条件方差**本身。条件怎么编码、条件多强、去噪器预测哪个量，都改不动它。

**解决九：把可微代理接进反向链（正，且经真值确认）。** 解决八把散度定位成「网络学到了整条条件分布，而不是 cs1 等于目标这个切片」。既然如此，与其重训去噪器去逼这个约束，不如在采样时用另一个模型把它推上去。这个模型已经存在：`spec_opt.SmoothSurrogate` 是冻结 MLP 代理的可微镜像（`adam` 基线一直在用它），而它正是选择层排序用的同一个模型，所以推的方向和排序的口径天然一致。

做法：每算出一个 x0 估计，就做一步对数 cs1 误差的梯度下降，步长 λ 乘 `abar[t]`（噪声大时 x0 本身不可信，纠正小；末端纠正满）。每步多一次解码加一次反向传播，采样时间 11 秒到 21 秒，不用重训，开关是 `--guide-lambda`。

λ 扫描（Steel 5000 / Steel 16000，各 3000 台，代理口径，每格「5000 / 16000」）：

| 0 | 0.160 / 0.126 | 0.029 / 0.046 | 0.175 / 0.220 | 0.328 / 0.408 | 11 s |

| 0.1 | 0.019 / 0.018 | 0.359 / 0.382 | 0.714 / 0.736 | 0.832 / 0.847 | 22 s |
| 0.2 | 0.249 / 0.187 | 0.025 / 0.086 | 0.129 / 0.228 | 0.252 / 0.345 | 22 s |
| 0.5 | 0.925 / 0.777 | 0.002 / 0.015 | 0.014 / 0.046 | 0.028 / 0.076 | 22 s |

λ = 0.05 是峰，0.2 起步长过冲反把批次推散，0.5 完全发散。λ = 0 那一行与不加引导的既有 CSV 逐字节一致，确认开关在 0 处是空操作。

代理口径在解决五与第 7 节都被真值推翻过，而梯度引导本质上就是「在采样里做优化」，所以必须过 ROSS。Steel 5000 rpm，每臂随机抽 300 台（`--select rand`，分别解出 299 与 300 台）：

真值确认这次不是代理幻觉：引导确实把批次的真值分布压到了目标附近。**这是第 5 节链路表里那个「整批只有 3.3% 落在 ±1% 内」第一次被真正动到。** 代价与限度：

- **多样性没有塌**：批次的中位配对距离（按真实 Steel 池子自身的四分位距归一）从 6.26 掉到 5.97，p90 从 13.33 到 10.88；交付短名单那层 5.55 到 5.38。设计仍然散开，只是散在目标附近。
- **200 台送验时看不出好处**：±1%、5000 台批次、200 台送验，无引导交付 103 台、引导交付 94 台（差 4.5 个百分点，se 5.0，噪声内）。这不是引导无效，是预算太小：无引导那条路线「代理排前 200」本来就顶在代理自己的精度上限（±1% 约 0.5）上；引导把整批底率从 2.7% 提到 30% 之后，代理在一个「人人都像在带内」的批次里反而排不出名次（它自称前 200 的预测中位误差是 0.0001）。
- **送验预算一放大就分开了**：同样 Steel 5000 rpm ±1%、同样 5000 台批次、同一个 seed，只把送验从 200 台放到 1000 台：

| 送验台数 | 无引导交付 | 引导 λ=0.05 交付 | 每交付一台 |
|---|---|---|---|
| 200 | 103 | 94 | 1.26 s / 1.38 s |
| 1000 | **163** | **494** | 4.0 s / 1.3 s |

  无引导从 200 台放到 1000 台只多交 60 台，因为它整批 5000 台里的在带设计本来就只有一百多台，已经接近上限；引导交 494 台，仍在按约一半的比例线性增长。**引导值不值是「你要多少台设计」的函数：一百台上下两条路等价，要几百台时引导便宜约 3 倍。**
- 还有一处不依赖 ROSS 的用法：整批直接交付时，±1% 上无引导只有 2.7% 可信、引导有 30.0%；±5% 上 17.1% 对 87.0%。

| 盘 3、轴承 2（钉死） | 170 | 1.000 | 0.987 | 0.86% | 0.63% | 0.545 |

两两 Fisher 精确检验：不限对钉死 p = 0.28，不限对「2 到 4」p = 1.00，「2 到 4」对钉死 p = 0.17，**没有显著差别**。此前用 20 台抽样得出的「限定家族后精度更好」是噪声，这里用 150 台否掉了。

MAPE 与中位 APE 上钉死 3x2 看起来更好（0.86% 对 1.24%、0.63% 对 0.81%），但这两臂没有落盘逐台真值，做不了配对检验，只能算方向性观察；`--dump-truth` 已加上，重跑一次即可判定。

**结论**：家族先验是用户约束机制，不是漏斗的性能杠杆。协议默认保持均匀；用户钉死池子里没有支撑的家族时要提示这是外推。

## 7. 基线

代码 `spec_baselines_latent.py`。七个基线全部搬进同一个 34 维隐空间，用同一个代理排序、同样交付 200 台，因此与生成式方法同口径。

| 方法 | 原理 |
|---|---|
| random_latent | 隐空间均匀采样，下界 |
| retrieval | 在池子里检索真在带内的设计，上限但新颖度为零 |
| retrieval_jitter | 检索加 1.5% 隐空间扰动，再按代理挑 |
| de | 隐空间上的差分进化 |
| ga | 隐空间上的遗传算法 |
| adam | 对代理目标做梯度上升（`latent_torch.py` 提供可微解码器），软约束罚项防止越界 |
| bo | 高斯过程 + EI 采集函数 |

结果（ROSS rand-40，六规格平均）：

| 方法 | 真值在带 | MAPE | 中位 APE | 代理在带 | 代理 − 真值 | 新颖度 | ROSS 失败 | 秒/规格 |
|---|---|---|---|---|---|---|---|---|
| retrieval | 1.000 | 1.87% | 1.05% | 0.799 | −0.201 | 0.00 | 0/240 | 1 |
| ga | 0.750 | 4.55% | 1.70% | 1.000 | +0.250 | 2.26 | 0/240 | 25 |
| adam | 0.575 | 7.70% | 3.82% | 1.000 | +0.425 | 2.62 | 0/240 | 55 |
| retrieval_jitter | 0.545 | 2.29% | 1.27% | 0.497 | −0.047 | 0.49 | 1/240 | 1 |
| de | 0.348 | 19.70% | 8.87% | 1.000 | +0.652 | 3.96 | 7/240 | 37 |
| bo | 0.125 | 17.80% | 10.80% | 0.128 | +0.003 | 4.01 | 5/240 | 33 |
| random_latent | 0.010 | 26.52% | 19.20% | 0.018 | +0.007 | 6.97 | 30/240 | 1 |
| **条件 DDPM（v1，即 armV_ema 模型 + 25 步）** | **0.962** | **1.58%** | **1.03%** | 1.000 | +0.058 | 2.18 | 0/240 | 1 |

三条读法：

- 乐观偏置随「离数据流形多远」排序：de 偏 +0.652、新颖度 3.96；ga 偏 +0.250、新颖度 2.26；本版偏 +0.058、新颖度 2.18。检索是唯一负偏（它交的就是池子里的真设计）。
- 排名被改写：代理口径下 DE 和 GA 都是 100% 在带，真值下只有 0.348 和 0.750，本版从 1.000 到 0.962。**代理选不出它自己交付的哪个更好**，这是「代理预选 + ROSS 复验」流程成立的前提，也正是第 5 节要解决的问题。
- 可分析性：random_latent 有 30/240 台送不进 ROSS（12.5%），de 7 台，bo 5 台，本版 0 台。
- 成本：检索 1 秒、DE 与 GA 25 到 37 秒、Adam 55 秒、BO 33 秒；条件 DDPM 训练一次约 22 分钟后每规格采样 1 秒。

## 9. 已知问题与下一步

1. **紧带没有「排序」解，只有「筛选」解**：±1% 与 ±0.5% 的真值在带只有 0.520 与 0.220，事后校准已被证否（第 5 节解决四），加大候选池也无效（解决五）。接口现在给的是闸门：`design_by_target.py --verify` 逐台解 ROSS，只交付实测在带的设计，成本 1.22 秒/台（±1%）、1.95 秒/台（±0.5%），±5% 只要 0.70 秒/台，所以「容差小于代理误差就拒答」不再是唯一选择。排序值多少已经量出来（15.7 倍，第 5 节解决五）。整批只有 3.3% 落在 ±1% 内、32.4% 落在 ±10% 内、中位目标距离 15.5%，说明条件的推力度够而散度大。条件侧改不动它（解决八：多尺度编码、去掉条件丢弃、x0 预测三条都否），改得动它的是采样期的可微代理引导（解决九）：真值口径下整批 ±1% 从 0.0268 到 0.3000、中位距离从 15.41% 到 1.72%。引导对闸门交付量的好处取决于送验预算：±1% 送验 200 台时 103 对 94（噪声内），送到 1000 台时 163 对 494。小预算下瓶颈是代理的排序精度，大预算下瓶颈是批次里究竟有多少在带设计，后者已被引导解决。
2. **闸门曲线只测了一条臂**：200 台整批求解没有抽样误差，但全部来自 Steel 5000 rpm、`armV_ema`、单 seed，换材料、换档位、换生成器都要重测。
3. **整批复验**：交付清单 0.933 到 0.987 与整批代理 0.18 是两个口径。要做「整批直接交付」就必须把复验从抽样扩到整批，成本约是每台 0.5 秒乘进程数。
4. **外推提示还没接进接口**：支撑面已经能量出「该带内有几台真实解」（第 2.2 节），`funnel_*.json` 也记了 `support_pool_band_family`，但采样器不会因为支撑为 0 或个位数而拒绝或告警。阈值和提示语待定。
5. **家族差异缺配对检验**：三条家族臂（0.86% 对 1.24% 的 MAPE 差异）没有逐台真值落盘，做不了配对检验。`--dump-truth` 已加上，重跑 300 台真值即可定论。
6. **家族先验的正确用武之地**是检索式基线：那里的几何就是池子里抽的，42 倍差距成立，先验能直接省下三分之二的检索预算。这条还没做。

## 12. 这份报告不能说明什么

- 第 5 节的 Stage B 数字来自 36 个批次的另一组 40 台抽样（1426 台真值），第 7 节的数字来自 `ross_verify_rand.json`（每规格 40 台）。两者都是 40 样本比例，噪声约 ±0.08，逐批次差异要按这个尺度读。
- 「真值在带 0.963」是对**代理挑出的前 200 台**抽样，不是对生成的 5000 台抽样。
- 命名：模型 tag 是 `armV_ema`，当前提交的 out-tag 是 `v1`。同一批提交的两次历史复验分别存为 `v1_r40`（随机抽 40 台）与 `v1_t40`（代理前 40 台），与本次 20 台复核是同一批设计的独立抽样。
- 第 5 节的偏移检验与第 6 节的家族 A/B 都是 n=150 的抽样（比例标准误约 0.025）；其中 top-20 的比例标准误约 0.11，所以偏移检验只能否掉「大幅受益」，不能排除小于 10 个百分点的改善。
- 家族三臂比较的是 MAPE 与中位 APE，但逐台真值未落盘，两条 MAPE 的差没有配对检验；`--dump-truth` 之后才可做。
- 偏移检验的 top-k 比较是在「被随机抽中的 150 台」内做的，等价于对交付的 200 台做无偏近似，不等于完整的 200 台重排序。
- 第 2.2 节的可达性面只回答「池子里有多少真实解」，它假设检索到的解都能被生成器复现；生成器自身的复现能力见第 4 节，两者不是同一件事。
- 闸门那张表的 ±1% 行是整批 200 台求解，没有抽样误差；但它只覆盖 Steel 5000 rpm 一条臂，换材料或换档位要重测。
- 闸门回答的是「代理交付的 200 台里哪些是真的」；整批有多少真的由 300 台无偏抽样回答（0.0334）。抽样只够定这一个数量级：要把 0.0334 分辨到 ±0.2 个百分点以内，需要约 5000 次求解。
- 解决八与解决九的批次宽度表都是 `--sample-steps 25` 口径。首轮编码实验漏了这个参数、跑成了整链 1000 步（`--sample-steps` 默认 0 不是 25），绝对数不能与本报告其他表比，已按 25 步全部重跑（`ab_25steps.csv`），旧文件已删。教训：默认值等于「全链」，不比 `--sample-steps 25` 便宜。
- 解决八的比较是 6 个目标 × 3000 台、同 seed、同家族抽样、同初始噪声的**配对抗**（t 值按 6 个目标的逐目标差算，是保守口径）；口径本身是代理，不是真值。
- 解决九的引导是对**代理**做似然上升，所以它的批次口径天然偏向代理。本次结论过了 ROSS 才写（Steel 5000 rpm、299 对 300 台随机抽样）；换材料、换档位、换 λ 都要重测。
- 解决九的闸门交付结论只测了 Steel 5000 rpm ±1%、单 seed，送验 200 台与 1000 台两档；1000 台那档引导臂有 2 台 ROSS 未返回（按 998 台计），对 49.5% 这个比例可以忽略。换材料、换档位、换 λ 都要重测。
- 批样本的 ±1% 在带率是 299 台解出的 0.0334，抽样标准误约 1.0 个百分点，与 `armN256` 的 0.023 分辨不开；两个模型的差别要到 ±10% 份额（0.324 对 0.247，约 2.8 个标准误）才可比。
- 链路表里「池子 0.0077」是 66377 台真实 Steel 设计的统计，不是抽样；它和生成批次的口径不同（真实设计对生成设计），只能当参照。
- 规格命名：`Steel_5000` 是 ±5%，`Steel_5000_t1` 是 ±1%，`Steel_5000_t05` 是 ±0.5%。2026-09-26 之前自动命名不带容差后缀，同一目标的第二个容差会覆盖第一条规格（已修并恢复）。
- 所有结论都基于 v4.7 数据集与 ROSS 的 `num_modes=48`、正阻尼正进动语义；换语义则全部作废。
