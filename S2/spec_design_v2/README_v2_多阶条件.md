# spec_design_v2 -- 多阶临界转速条件（cs1 / cs2 / cs3 任意组合：点值或区间，容差 ±5 %）

日期：2026-10-02　　上游：`S1/04_versions/v4.7`（199 811 台 success 转子，六阶齐全）
骨架：`spec_design`（v1，单阶 cs1 条件）。反向链、解码器、代理、引导**全部复用 v1**，没有第二份实现。

---

## 1. 一句话结论

**条件 1 已满足：cs1 / cs2 / cs3 的 7 种非空组合，±5 % 容差下全部实测通过，交付量 57–192 台。**

| 用户想要 | 候选数 | **±5 % 交付**（200 台预算） | 同批随机 200 台对照 | 参考：±1 % |
| --- | --- | --- | --- | --- |
| cs1 单独 | 5 000 | **192 台** | 161 台 | 99 台 |
| cs2 单独 | 5 000 | **186 台** | 150 台 | 81 台 |
| cs3 单独 | 5 000 | **183 台** | 132 台 | 60 台 |
| cs1 + cs2 | 5 000 → 20 000 | 162 → **174 台** | 41 → 27 台 | 28 台 |
| cs1 + cs3 | 5 000 | **161 台** | 27 台 | 17 台 |
| cs2 + cs3 | 5 000 | **141 台** | 27 台 | 16 台 |
| cs1 + cs2 + cs3 | 5 000 → 20 000 | 57 → **131 台** | 5 → 0 台 | **0 台** |

三阶臂是唯一需要照顾的：候选数从 5 000 抬到 20 000，交付从 57 台涨到 131 台。
生成本身只要几十秒，贵的是 ROSS 复验，所以这个旋钮很划算（详见 §5 洞察③）。

**另外，盘数 / 轴承数也是可选项**：不限制、给范围（1-2 / 2-4）、或固定（2-2）都支持，可以和上面任意
组合叠加。实测限定家族几乎不花钱，固定时甚至略好（cs1 197 台、cs1+cs2 169 台）。见 §4.3。
唯一要注意的是目标转速得落在「每个家族都够得着」的窗口里，`01_family_window.py` 用来查这个。

**区间规格（§4.4）和联立（§4.6）可以叠加**：每一阶都能写成点值或范围（含单边「至少多少」），
任意挑几阶同时给，两种写法混用；家族可以生成前限定，也可以生成后筛选。实测
`cs1∈[3000,4500] 且 cs2∈[6000,9000]` 真值精确落在用户区间内 **174 / 200**，再加 cs3 是 **168 / 200**。
家族条件还有一个「候选数开多大」的问题，两条曲线都扫了：同样交付 192 台，
生成前限定要 20 000 候选、生成后筛选要 10 000 候选，价格几乎一样（见 §4.7）。

「单独考虑某一阶」是这一版真正打开的能力，代价基本为零（cs2、cs3 单独和 cs1 单独一样便宜）。
联立越深、候选越稀，同一批 5 000 台里能被抓出来的设计就越少——但把候选数抬到 20 000 就能补回来，
因为采样本身只要几十秒，贵的是 ROSS 复验，不是生成。

## 2. 这一版改了什么

### 2.1 条件向量：从「一个数」变成「值 + 开关」

v1 的条件只有 13 维：`material(3) | family(9) | z(log cs1)`。
v2 换成三阶带掩码（mask），共 18 维：

```
condition = [ material one-hot (3) | family one-hot (9) | z1 m1 z2 m2 z3 m3 ]
                                                            ^^^^^ ^^^^^
                                                            z_j  z-score 的 log cs_j 目标值（未被要求时填 0）
                                                            m_j  1 = 用户要求了这一阶
```

- **一次训练覆盖全部 7 种非空组合**：训练时每台转子随机抽一个阶子集
  （`--mask-policy mixed`，k=1/2/3 权重 0.45/0.35/0.20），mask **按 epoch 固定**——
  每个 batch 重抽会把条件本身变成噪声。
- 采样时用户给 `--targets 1=3680.8,2=7021`，没写的阶把 m 置 0，网络自然退化到「只钉这两阶」。
  cs1-only 分支在行为上等价于 v1，老协议不用废。
- **逐阶独立 z-score**：cs1 跨 3.6 个数量级、cs3 只有 2.9，共用一个均值会把 cs3 通道压成常数，
  mask 就浪费了。

### 2.2 除了条件，其它一律不动

潜在空间（34 维）、解码器、冻结的六阶代理（`mlp_best`，5-seed 几何平均）、cosine 噪声表、
v1 验证过的可微引导 `--guide-lambda 0.05`（多阶的联合损失按阶数归一化，免得钉三阶时一步走三步远）
——全部沿用。所以这一版的提升可以干净地归因到「条件表达方式」这一件事上。

### 2.3 训练池的两个数字（别混用）

- **199 808**：v2 训练池。只要求 cs1/cs2/cs3 有标签，末阶删失不影响，只丢 3 台。
- **192 962**：可达性分析（`00_feasibility.py`）的池子。它要求六阶全有，被 cs6 的 6 849 台删失拖下来。

两者差的是 cs4–cs6 的空标签，对 cs1–cs3 的条件没有影响，对照时不要当成同一批数。

## 3. 可行性（数据侧，先于模型）

192 962 台真值上直接数（`outputs/feasibility.json`）：

**相关性**　corr(log cs1, log cs2) = 0.854　corr(log cs2, log cs3) = 0.642　corr(log cs1, log cs3) = 0.571

**把 cs1 钉死在 ±1 % 之后 cs2 / cs3 还剩多少自由度**（IQR 占中位数的百分比）：

| cs1 目标 | cs2/cs1 的 IQR | cs3/cs1 的 IQR |
| --- | --- | --- |
| 1230 | 57 % | 150 % |
| 3681 | 57 % | 96 % |
| 12226 | 43 % | 87 % |

→ 自由度远没有塌掉，cs2 / cs3 不是 cs1 的复述，**分开写条件是有信息量的**。

**联合支撑**（真实数据里同时满足的台数，每个 cs1 带内约 350–500 台）：

| 组合 | ±1 % | ±5 % |
| --- | --- | --- |
| cs1 | 261–538 | 1 335–2 613 |
| cs1 + cs2 | 5–16 | 136–256 |
| cs1 + cs3 | 3–14 | — |
| cs1 + cs2 + cs3 | 0–2 | 6–30 |

**代理自身误差 vs 用户要的带宽**：

| 阶 | 冻结代理 MAPE | ±1 % 带宽 / MAPE | ±5 % 带宽 / MAPE |
| --- | --- | --- | --- |
| cs1 | 1.28 % | 0.78 | 3.9 |
| cs2 | 2.19 % | 0.46 | 2.3 |
| cs3 | 3.22 % | 0.31 | 1.6 |

→ **±5 % 的带比代理误差宽**，代理排得出名次，所以 ±5 % 是这一版的实际工作点；
±1 % 时带比代理误差还窄，代理只能预筛，交付必须台台过 ROSS（第 5 节洞察②）。

## 4. 实测

统一目标取自 `feasibility.json` 里 Steel / Aluminum 上支撑最厚的邻域：
Steel cs1 = 3680.8、cs2 = 7021、cs3 = 17970.5 rpm；Aluminum cs1 = 3191.1、cs2 = 6147.6 rpm。
生成用 v1 的推荐配置（`--guide-lambda 0.05`、25 步、单 seed），短名单 200 台逐台送 ROSS，真值口径。

### 4.1 整批候选的代理口径（只看采样散不散，不进 ROSS）

| 条件 | 候选数 | 联合在带 @5 % | 中位联合误差 | 各阶边缘命中 @5 % |
| --- | --- | --- | --- | --- |
| cs1 | 5 000 | **88.7 %** | 1.20 % | cs1 88.7 % |
| cs2 | 5 000 | **87.5 %** | 1.32 % | cs2 87.5 % |
| cs1 + cs2 | 5 000 | 15.4 % | 13.76 % | 27.6 / 29.4 % |
| cs1 + cs2 | 20 000 | 16.5 % | 13.55 % | 30.5 / 31.6 % |
| cs1 + cs2 + cs3 | 5 000 | 1.26 % | 29.79 % | 19.5 / 22.5 / 18.6 % |
| cs1 + cs2 + cs3 | 20 000 | 1.63 % | 29.12 % | 19.5 / 22.5 / 18.6 % |

单阶条件能把整批推到近 90 % 落在 ±5 % 内；一旦联立，**每一阶的边缘命中率同步跌到 20–30 %**，
联合起来只剩百分之十几。这是条件维数上去后网络把概率质量摊开的结果，不是某一阶特别难。
**注意最后两行**：候选数从 5 000 涨到 20 000，整批在带率几乎不动（1.26 % → 1.63 %），
但短名单交付量大涨（下一节）——说明瓶颈在「从稀有的在带样本里挑」，不在「采样能不能覆盖」。

### 4.2 ROSS 真值，±5 %（当前启用口径）

| 条件 | 候选数 | 代理自称在带 | **真值在带** | **闸门交付** | 随机对照（同批 200 台） | 逐阶真值中位 APE |
| --- | --- | --- | --- | --- | --- | --- |
| cs1 | 5 000 | 1.000 | **0.960** | **192 / 200** | 161 台 | 1.03 % |
| cs2 | 5 000 | 1.000 | **0.930** | **186 / 200** | 150 台 | 1.49 % |
| cs3 | 5 000 | 1.000 | **0.915** | **183 / 200** | 132 台 | 1.60 % |
| cs1+cs2 | 5 000 | 1.000 | **0.814** | **162 / 199** | 41 台 | 1.53 / 1.68 % |
| cs1+cs2 | 20 000 | 1.000 | **0.870** | **174 / 200** | 27 台 | 1.14 / 1.56 % |
| cs1+cs3 | 5 000 | 1.000 | **0.805** | **161 / 200** | 27 台 | 1.53 / 1.98 % |
| cs2+cs3 | 5 000 | 1.000 | **0.705** | **141 / 200** | 27 台 | 1.91 / 2.26 % |
| cs1+cs2+cs3 | 5 000 | 0.315 | **0.285** | **57 / 200** | 5 台 | 3.56 / 3.34 / 3.32 % |
| cs1+cs2+cs3 | 20 000 | 1.000 | **0.655** | **131 / 200** | 0 台 | 2.22 / 2.16 / 2.30 % |
| Aluminum cs1+cs2 | 5 000 | 1.000 | **0.790** | **158 / 200** | 25 台 | 1.41 / 1.78 % |

三阶臂的逐阶 APE 从 3.3 % 降到 2.2 %（候选数 5 000 → 20 000），说明**候选多了，代理选出来的东西本身就更好**，
不只是「挑得更准」。§5 洞察③ 给了这笔账。

**换材料换目标点复核**（最后一行）：Aluminum cs1 = 3191.1 + cs2 = 6147.6，交付 158/200，
和 Steel 的 162/199 是同一水平 → 这个能力不是某一材料或某一目标点的巧合。

耗时：采样 5 000 台含引导 17–26 s、20 000 台约 140 s（10 线程）；
ROSS 200 台约 125 s（18 进程，≈0.63 s/台），摊到每一台交付上来算就是表里的 0.7–0.9 s。

### 4.3 家族（几盘几轴承）作为可选条件

盘数和轴承数本来就在条件向量里（`family one-hot (9)`），所以「不限制 / 给范围 / 固定」三种输入
不需要重训，只要在采样时告诉它允许哪些家族。输入形式和 §6 的 `--disks` / `--bearings` 一致：

| 用户想说的 | 输入 |
| --- | --- |
| 不限制 | 不加参数（18 个家族均匀抽） |
| 盘 1–2、轴承 2–4 | `--disks 1-2 --bearings 2-4`（6 个家族） |
| 盘固定在 2、轴承固定在 2 | `--disks 2-2 --bearings 2-2`（1 个家族） |
| 只限盘、轴承随便 | `--disks 3-3` |
| 只限轴承、盘随便 | `--bearings 2-2` |

实测（Steel，±5 %，目标取该家族自己的转速中位数）：

| 目标 | 盘 / 轴承 | 候选数 | 真值在带 | **闸门交付** | 随机对照 |
| --- | --- | --- | --- | --- | --- |
| cs1 = 2 974 | 固定 3 盘 2 轴承 | 5 000 | 0.990 | **197 / 199** | 161 台 |
| cs2 = 8 180 | 固定 2 盘 2 轴承 | 5 000 | 0.935 | **187 / 200** | 171 台 |
| cs1 = 2 974 + cs2 = 7 001 | 固定 3 盘 2 轴承 | 5 000 | 0.845 | **169 / 200** | 28 台 |
| cs1 = 4 642 + cs2 = 9 969 | 范围 1–2 盘 / 2–4 轴承 | 5 000 | 0.775 | **155 / 200** | 29 台 |
| cs1+cs2+cs3 = 2 974 / 7 001 / 20 359 | 固定 3 盘 2 轴承 | 20 000 | 0.615 | **123 / 200** | 1 台 |

**结论：限定家族几乎不花钱，固定时甚至更好。**
和「不限制」的同档对照：cs1 是 197 对 192 台、cs2 是 187 对 186 台、cs1+cs2 是 169 对 162 台
（都是固定的略好，因为家族钉死后流形更窄、更好学）；只有三阶是 123 对 131 台，略低。
给范围的 155 台介于两者之间。→ 这个可选项可以放心开给用户。

**但有一个必须配套的约束：目标转速要落在「每个家族都够得着」的窗口里。**
家族对能跑多快影响极大——Steel 各家族的 cs1 中位数从 **2 066 rpm（6 盘 2 轴承）到 6 050 rpm（1 盘 4 轴承）**。
给的范围越宽，这个公共窗口越窄：

| 盘 / 轴承 | cs1 公共窗口 | cs2 | cs3 |
| --- | --- | --- | --- |
| 1–2 盘 / 2–4 轴承（6 族） | 3 126 – 6 574 rpm（2.10×） | 6 301 – 15 109 | 17 340 – 49 559 |
| 3 盘 / 2 轴承（1 族） | 1 611 – 5 288 rpm（3.28×） | 3 751 – 12 821 | 11 947 – 39 954 |

超出公共窗口不是不能生成，只是够不着的那些家族白占名额，交付量会掉。
新增 `01_family_window.py` 就是查这个的：

```powershell
& $PY 01_family_window.py --material Steel --disks 1-2 --bearings 2-4
```

每个家族在数据里有 2 749–4 559 台 Steel 转子（18 个家族合计 66 376 台），支撑是够的。

### 4.4 区间型规格：`1=[10000,12000]` 和 `1=[14400,+]`

临界转速的输入现在有两种写法，可以混用、可以和 §4.3 的家族条件叠加：

| 写法 | 含义 | 判定口径 |
| --- | --- | --- |
| `--targets 1=3680.8 --tol 0.05` | 点值 ± 容差 | 落在 ±5 % 内 |
| `--targets "1=[10000,12000]"` | 区间 | 落在用户给的区间内（`--tol` 默认 0） |
| `--targets "1=[14400,+]"` | 单边（只要裕度） | ≥ 14400 |
| `--targets "1=[10000,12000],2=[5000,+]"` | 混合，任意阶 | 逐阶各按各的 |

**为了让网络真的"填满"一个区间，新增了区间条件版模型 `v2i`**：条件从「每阶一个数」改成
「每阶两条边」，训练时给每台转子随机发一个包含它自己转速的区间——40 % 是退化区间（等于点规格）、
25 % 是单边区间（等于"只要大于"这种裕度规格）、其余是各种宽度的双边区间。点版 `v2m` 保留，
它在处理区间时只能取几何中心。

同一批区间目标，两个模型对比（Steel，5000 台候选，短名单 200 台逐台 ROSS）：

| 用户给的区间 | 整批在带（点版 / 区间版） | **交付**（点版 / 区间版） | 区间内五等分的填充比 max/min（点版 / 区间版） |
| --- | --- | --- | --- |
| [3500, 3870]（10 %） | 0.358 / 0.363 | 155 / 154 | 2.11 / 2.01 |
| [2600, 5200]（2×） | 0.769 / 0.783 | 192 / 194 | **1.77 / 1.16** |
| [1800, 7500]（4.2×） | 0.960 / 0.968 | 197 / 198 | **2.82 / 1.96** |
| [3681, +]（单边） | 0.757 / **0.894** | 194 / 197 | **2.68 / 1.72** |

**怎么读这张表：**
- **交付量上，区间几乎是免费的**——点版模型天然就会散开 ±10–20 %，所以用户给的区间只要比这个宽，
  它就已经能填。两种情况（点版/区间版）在交付数上是平的。
- **区间版买到的是"填得匀"**：点版会把 5000 台堆在区间的一头（宽区间尤其明显，最密的一格是最疏的 2.8 倍），
  区间版把这个比压到 1.16–1.96。对"从一批里挑设计"的用法，这直接等于**可选范围更大**，
  而不是 200 台近亲。
- **单边规格收益最实在**：整批在带率从 0.757 升到 0.894，少浪费 14 % 的候选。
- **窄区间没什么可改的**（2.11 → 2.01），因为区间比模型自身的散布还窄，本来就没有宽度可利用。

**区间版能当唯一点模型用。** 同一份 `v2i` 在点规格 `cs1 = 3680.8 ± 5 %` 下交付 186/199，
点版 `v2m` 是 192/200；±1 % 下是 102/199 对 99/200——两者统计上分不开。
所以默认入口已经切到 `v2i`：**一个 checkpoint 同时服务点规格和区间规格。**

**一个必须说清楚的边界**：网络能填的区间有上限，日志宽 0.70（约 4 倍）。超出的部分自动收窄
（双边区间绕几何中心收，单边区间贴下边界收，见 `spec_interval.effective`）。所以
`[1800, 7500]` 实际填的是 `[2589, 5214]`，用户给的区间仍然是**判定**口径——落在里面就算交付，
只是别指望设计均匀铺满整个 4 倍以上的大区间。

```powershell
& $PY design_by_target_v2.py --targets "1=[10000,12000]" --material Steel --verify
& $PY design_by_target_v2.py --targets "1=[14400,+]" --material Steel --verify
& $PY design_by_target_v2.py --targets "1=[2600,5200],2=[5000,+]" --material Steel --tol 0 --verify
& $PY run_v2_interval.py --n-generate 5000 --threads 10 --workers 18   # 复现 4.4 整张表
```

### 4.6 区间 + 多阶联立，以及「生成前限定家族」vs「生成后筛选」

§4.4 打开了单阶区间，§4.3 打开了家族条件，这一节把三件事叠在一起：**每一阶都可以写成点值或
区间，任意挑几阶同时给，两种写法混用，家族可以生成前限定也可以生成后筛选**。五条查询全部
走 ROSS 真值，判定口径是「真值是否落在用户写的区间内」（`--tol 0`）：

| 用户查询 | 候选数 | **精确落在用户区间**（真值） | ±5 % | ρ |
| --- | --- | --- | --- | --- |
| cs1∈[3000,4500] **且** cs2∈[6000,9000] | 5 000 | **174 / 200** | 195 / 200 | 0.768 |
| 再加上 cs3∈[14000,22000] | 5 000 | **168 / 200** | 197 / 200 | 0.715 |
| cs1=3680.8 **且** cs2≥6000（点值 + 单边混用） | 5 000 | 170 / 200（±5 %） | — | −0.03 |
| cs1∈[3000,4500]，家族**生成前**固定 3盘2轴承 | 5 000 | **181 / 200** | 196 / 200 | 0.812 |
| 同上，家族**生成后**筛选（20000 台 → 留存 1 099 台） | 20 000 | **192 / 199** | 199 / 199 | 0.931 |

逐阶真值（第一行）：cs1 落在区间里 0.915、cs2 0.945、**两阶同时** 0.870；三阶那行是
0.955 / 0.950 / 0.920，**三阶同时** 0.840。中位偏差全是 0.00 %——落在区间内就算 0，
这正是区间口径该有的样子。

**怎么读：**

- **区间 + 联立是可行的，而且比点值联立好做。** §4.2 里 cs1+cs2 用点值 ±5 % 是 162 台
  （5 000 候选），这里两阶都给范围、同样 5 000 候选就是 174 台；三阶更明显——点值口径要
  20 000 候选才 131 台，区间口径 5 000 候选就有 168 台。原因很直白：半宽 22 % 的区间比
  ±5 % 的点带宽容得多，而判定口径就是用户写的那条带，没有额外收紧。
- **联立目标比单阶稀疏得多，这是数据事实，不是网络问题。** `02_joint_support.py` 查真实
  数据池：Steel 66 376 台里，cs1∈[3000,4500] 且 cs2∈[6000,9000] 有 **3 747 台（5.6 %）**，
  再加上 cs3∈[14000,22000] 只剩 **1 027 台（1.5 %）**。所以下单之前先查一次支撑度，
  低于几十台就别指望生成+复验能变出设计来。
- **点值 + 单边的混用有一个坑**：ρ ≈ 0，代理在短名单内部排不动序。不是网络退化了，是这 200 台
  的真实 cs1 本来就挤在一起（中位偏差 1.47 %、p90 7.77 %），彼此差距落在代理自身误差以下，
  名次就是噪声。交付 170/200 靠的是**批次本身集中**，不是排序——这一档如果要用，排序信息不要信。
- **生成后筛选不是「等价替代」，是另一条曲线。** 同样固定 3盘2轴承：生成前限定拿到 5 000 台
  目标家族候选，交付 181/200；生成后筛选花 4 倍候选数（20 000 → 留存 1 099 台），交付
  192/199。**质量更好、成本更高**，而且 ρ 从 0.812 升到 0.931：免费采样把家族撒开之后，
  幸存者的设计更多样，短名单不再是近亲，代理排序反而更可信。这一对的性价比在 §4.7 扫开了：
  按「同样交付 192 台」比，两条路价格几乎一样（0.75 对 0.79 s/台），所以选哪条看用途——
  要一批里家族多样就用生成后筛选，否则生成前限定更省事。

### 4.7 家族条件：候选数该开多大（两条曲线）

§4.6 只比了一对（生成前限定 5 000 对生成后筛选 20 000），结论「4 倍候选换 +11 台」是在两个
不同的交付量上比的，不公平。这一节把候选数扫开，**ROSS 预算固定每臂 200 台**，规格固定
cs1∈[3000,4500]、家族 3盘2轴承，于是表读起来就是：给我 200 次求解的预算，我能交付几台，采样要花多少。

| 家族怎么限定 | 生成候选 N | 留存（目标家族） | **交付（精确在带）** | ±5 % | ρ | 生成耗时 | 每交付一台总耗时 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 生成前限定 | 5 000 | 5 000 | 181 / 200 | 196 | 0.812 | 11 s | **0.62 s** |
| 生成前限定 | 20 000 | 20 000 | **192 / 200** | 200 | 0.926 | 35 s | 0.79 s |
| 生成后筛选 | 5 000 | 263 | 156 / 198 | 198 | 0.896 | 17 s | 0.87 s |
| 生成后筛选 | 10 000 | 502 | **192 / 199** | 198 | 0.917 | 25 s | **0.75 s** |
| 生成后筛选 | 20 000 | 1 099 | 192 / 199 | 199 | 0.931 | 43 s | 0.86 s |
| 生成后筛选 | 40 000 | 2 138 | 188 / 200 | 198 | 0.932 | 76 s | 1.04 s |

「每交付一台总耗时」= （生成耗时 + 200 次 ROSS 求解）／交付台数，是真正该看的成本。

**怎么读：**

- **生成前限定也需要把候选数给够。** 5 000 只有 181 台，抬到 20 000 是 192 台，ρ 从 0.812
  升到 0.926。原因是最优 N 选一：代理排序有误差，候选池越大，前 200 名里真正好的越多。
  §4.3 说的「限定家族几乎不花钱」是相对**点值条件**说的（197 对 192），不是「5 000 就够」。
- **生成后筛选在 10 000 处饱和。** 5 000 时只留存 263 台，连 200 台短名单都凑不满，交付掉到
  156；10 000（留存 502 台）就回到 192 台，再往上到 40 000（留存 2 138 台）不涨反落一点，
  在噪声里。
- **两者在同样交付量上打平。** 同样交付 192 台：筛选 10 000 是 0.75 s/台，限定 20 000 是
  0.79 s/台，基本同价（ρ 也接近，0.917 对 0.926）。最便宜的是**限定 5 000（0.62 s/台）**，
  但它只能交付 181 台——之前那句「4 倍成本」说的就是这个不用花的那 4 倍，现在知道它只值 11 台。
- **建议**：默认 **生成前限定 + 20 000 候选**（ρ 最高、口径最干净、不多一步筛选）；
  需要同一批里保留家族多样性、或者不想提前钉死家族，用 **生成后筛选 + 10 000**，价格几乎一样。

```powershell
& $PY run_v2_family_sweep.py --threads 10 --workers 18   # 复现整张表，约 25 分钟
```

## 5. 三个必须写进结论的洞察

**① 「代理自称 100 % 在带」仍然是假的，但短名单不是没用。**
±5 % 单阶下代理自称全在带、实测 96 %；cs1+cs2 这一档是 **162 台对随机的 41 台**，
cs1+cs2+cs3（20 000 候选）是 **131 台对随机的 0 台**。生成+引导真正干的事是把稀有的在带设计
浓缩进短名单，代理负责粗筛，ROSS 负责发证。把这三件事分开说，就没有过度承诺。

**② 短名单内部的排序能力会「饱和失效」，这决定了 ROSS 预算怎么花。**
ρ(代理联合误差, 真值联合误差)：短名单 200 台内 cs1 是 0.05、cs2 是 −0.07、cs1+cs2 是 0.03、cs1+cs2 是 0.06
——基本是噪声；而在同批随机 200 台里是 0.59 / 0.43 / 0.96 / 0.95。
原因很直接：短名单内代理 APE 中位数只有 0.4–1.0 %，所有候选在代理眼里长得一模一样，名次没有信息。
工程含义：**单阶和两阶不要纠结「前 10 名」，200 台一起送验**；三阶（ρ = 0.16–0.48）名次还有一点用。

**③ 联立情形下，加候选数比加网络容量便宜。**
三阶臂从 5 000 台提到 20 000 台，采样从 35 s 到 140 s（多 105 s），交付从 57 台到 131 台（多 74 台），
摊下来每多交付一台只要 1.4 s 的生成成本，而每交付一台的 ROSS 成本是 0.9 s。
**加候选是目前最划算的杠杆**，而且不用重训。

## 6. 怎么用：一条命令出交付清单（`s2_design.py`，推荐）

`s2_design.py` 是这一版的门面：输入人类写的规格，直接产出**一个交付文件夹**（清单 + 汇总 + 完整报告）。

```bash
# 一阶落在 3000-4500（区间目标，默认容差 0，默认做 ROSS 复验）
python s2_design.py --spec "cs1=3000-4500" --material Steel

# 一阶 + 二阶联立
python s2_design.py --spec "cs1=3000-4500, cs2=6000-9000" --material Steel

# 点值 + 5 % 容差
python s2_design.py --cs1 3681 --material Steel --tol 5%

# 单边「不低于」，并限定 3 盘 2 轴承（生成前限定）
python s2_design.py --spec "cs1>=3681" --material Steel --disks 3-3 --bearings 2-2

# 生成后再按盘数筛选
python s2_design.py --spec "cs1=3500-3870" --material Steel --filter-disks 2-4

# 只想快看一眼：不做 ROSS（结果**不保证**真实在带）
python s2_design.py --spec "cs1=3000-4500" --material Steel --proxy-only
```

规格写法（多项用逗号隔开，阶数 1..6）：

| 写法 | 含义 |
| --- | --- |
| `cs1=3681` | 点值（默认容差 ±5 %） |
| `cs1=3000-4500` | 区间（默认容差 0，就是用户给的范围） |
| `cs1>=3681`、`cs1=3681+`、`cs1=3681-` | 单边「不低于」，三种写法等价 |
| `1=[3000,4500]` | 原生写法，也认 |

产出（`outputs/delivered_<tag>/`）：

| 文件 | 内容 |
| --- | --- |
| `deliverable.csv` | **交付清单**：通过 ROSS 复验的设计，含全部几何参数 |
| `shortlist_with_truth.csv` | 短名单全部候选的真值（含没通过的），用来复盘 |
| `summary.md` | 人可读清单：规格、交付台数、各阶误差、前 20 台一览 |
| `summary.json` | 同上，机器可读 |
| `report.json` | 完整报告：代理口径 vs 真值、排序可信度 ρ、每台交付的仿真成本 |

实测（800 台候选 → 前 20 台送 ROSS，约 30 秒）：

```text
[规格] cs1 3500 - 3870   材料 Steel   容差 +-0%
[结果] 交付 18 台（ROSS 实测在带）｜ 代理自报 100% → 真值 90% ｜ rho 0.82 ｜ 0.81 秒/台
```

参考耗时：默认 5 000 台候选、200 台复验 —— 采样 10-35 秒，ROSS 约 2-4 分钟（18 进程）。
`--proxy-only` 只要采样那十几秒，但交付清单没有经过真值验证，只能当预览。
